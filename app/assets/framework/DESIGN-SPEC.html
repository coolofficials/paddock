차분한 생산성 도구를 위한 공통 기준. 2026년 10월 17일.

기본 Pretendard · 비교 SUIT. 본문 16px · 행간 1.8 · 한글 자간 0. 서체 선택은 미리보기와 공유됩니다. 글자 확대는 이 문서에 적용되며 창 배율과는 별도입니다.

1. 적용 범위와 고정 규칙

여러 개인용 데스크톱 앱에서 같은 시각 언어와 조작 방식을 사용합니다. 기준은 ‘차분한 생산성 도구’입니다. 실행할 일과 현재 상태가 먼저 보이고, 탐색과 장식은 작업을 뒷받침합니다.

버전 1.1의 공통 기준은 Pretendard, Lucide, 중립색 Slate, 강조색 Indigo입니다. 구현 기술은 정하지 않습니다. HTML과 CSS 예제는 Electron·Tauri 등 웹 기반 앱의 출발점으로 사용할 수 있고, WinUI·WPF·SwiftUI에서는 같은 토큰과 동작 규칙을 해당 플랫폼의 컴포넌트에 매핑합니다.

프로젝트마다 강조색, 버튼 모양, 패딩을 새로 만들지 않습니다. 공통 규칙 변경은 버전으로 기록하고 여러 앱에 함께 반영합니다. 도메인에 꼭 필요한 새 패턴은 확장 이름으로 추가하며 기존 컴포넌트 의미를 바꾸지 않습니다.

2. 폰트와 정보 계층

기본 UI는 Pretendard Variable 1.3.9로 구성합니다. 기준서와 미리보기에서 SUIT Variable 2.0.5를 비교 선택할 수 있습니다. 기본 서체 한 개가 현대 한글 완성형 11,172자(U+AC00–U+D7A3)를 모두 포함해야 합니다. 기본 모드의 영문과 숫자도 같은 패밀리를 사용합니다. 코드·로그·식별자에만 시스템 고정폭 폰트를 사용하며, 다른 고정폭 폰트를 번들링하면 별도의 라이선스를 포함합니다.

SUIT 비교 모드는 한글 2,668자를 포함합니다. 포함하지 않은 완성형 한글 8,504자와 em dash(U+2014)는 함께 제공하는 Pretendard로 대체하도록 지정한 예외입니다. 이 범위의 혼합 서체 표시와 실제 줄바꿈 검증은 대기 중입니다. 폰트의 문자 매핑(cmap)에 NFD 자모가 직접 없다는 사실만으로 조합 문자열이 표시되지 않는다고 판단하지 않으며, 조합·정규화에 따른 실제 렌더링은 따로 확인합니다.

조작 UI 행간은 1.6, 긴 읽기 본문은 1.8, 제목은 1.45입니다. 기준서·도움말은 16px 본문과 최대 약 42자 분량의 한글 행 길이를 기준으로 합니다. 한글은 어절을 유지하되 긴 경로와 공백 없는 문자열은 영역 안에서 줄바꿈합니다. 본문에 얇은 굵기를 사용하지 않습니다. 필수 정보를 작은 글자나 희미한 색으로 밀어내지 않습니다. 한글 본문과 제목 모두 자간 0을 기본으로 하며 음수 자간을 적용하지 않습니다. 밀집 모드에서도 필수 UI 15px, 보조 정보 13px 기준은 유지합니다. 정렬이 필요한 수치에는 고정폭 숫자를 사용합니다. 긴 파일명과 경로는 전체 내용을 열거나 확인할 수 있어야 합니다.

크기는 rem으로 매핑하고 운영체제 배율과 사용자의 글자 확대를 존중합니다. 200% 확대 시에도 입력과 주요 동작에 접근할 수 있어야 합니다.

3. 색상과 상태

Slate는 배경·텍스트·테두리, Indigo는 주요 동작·선택·포커스에 사용합니다. 색상 이름 대신 text, surface, selection, danger-text처럼 역할을 참조합니다. 라이트와 다크는 역할을 유지하면서 값을 바꿉니다.

상태를 색으로만 전달하지 않습니다. 프로젝트나 폴더마다 임의로 다른 색을 배정하지 않습니다. 배지·차트의 의미가 있다면 레이블과 매핑을 고정합니다. 선택 상태를 성공 상태와 혼용하지 않습니다.

본문·레이블·필수 보조 텍스트는 실제 배경과 대비 4.5:1 이상, 기능을 구분하는 아이콘·입력 경계·포커스는 3:1 이상을 기준으로 검증합니다. 장식적인 구분선은 이 입력 경계와 별도 토큰을 사용합니다. 모든 색상 조합이 자동으로 통과하는 것은 아니며 실제 인접 배경을 검사합니다.

4. 간격과 화면 밀도

간격은 4·8·12·16·20·24·32·40·48px을 사용합니다. 아이콘과 레이블 사이는 8px, 관련 필드 사이는 16px, 섹션 사이는 24~32px입니다. 컨트롤 모서리는 6px, 패널은 10px, 대화상자는 12px입니다.

모드컨트롤 높이목록 행 최소 높이
여유 모드 기본36px48px
밀집 모드32px40px

밀집 모드에서도 글자 크기와 포커스 표시는 줄이지 않습니다. 텍스트가 줄바꿈되면 높이가 늘어나도록 합니다. 포인터 대상은 데스크톱에서 최소 32px, 터치 등 거친 포인터 환경에서는 44px을 프로젝트 기준으로 삼습니다. 이는 이 프레임워크의 선택이며 WCAG의 모든 예외를 요약한 수치가 아닙니다.

그림자와 테두리는 겹침과 영역 구분에 사용합니다. 모든 영역을 카드로 감싸거나 유리 효과·그라데이션으로 장식하지 않습니다. 운영체제의 기본 창 재질은 플랫폼 기준을 따릅니다.

5. 세 가지 화면 패턴

목록과 상세

여러 파일·기록·작업을 선택해 다루는 앱에 사용합니다. 전역 탐색 208px, 작업 목록은 유동 너비, 상세 패널은 280px을 기본으로 합니다. 선택한 항목과 상세 내용은 항상 일치해야 합니다. 창이 좁아지면 상세를 아래 영역이나 명시적으로 여는 패널로 옮깁니다. 선택과 스크롤 위치를 유지합니다.

편집 작업 공간

메모·문서·이미지처럼 하나의 내용을 오래 편집하는 앱에 사용합니다. 중앙 편집 영역이 가장 넓고, 도구는 상단, 속성은 필요한 경우에만 옆에 배치합니다. 탭과 문서 제목은 저장 상태를 함께 전달합니다. 편집에 필요한 공간을 대시보드 카드로 대체하지 않습니다.

소형 도구

텍스트 변환·빠른 캡처·실행기처럼 짧은 작업에 사용합니다. 입력 → 결과 → 실행 또는 복사 순서로 구성합니다. 탐색 대상이 하나뿐이면 사이드바를 두지 않습니다. 결과가 생긴 뒤 다음 행동을 가까이 둡니다.

상단에는 위치와 전역 도구, 화면 제목 옆에는 그 화면의 대표 동작, 목록 위에는 검색과 필터를 둡니다. 새 창에서 실제 사용 가능한 크기와 큰 글자 환경을 먼저 확인합니다. 너비가 부족할 때 내용을 잘라내거나 가로 스크롤을 전체 화면에 만들지 않습니다. 데이터 표와 편집 캔버스의 가로 스크롤은 해당 영역 안에 한정합니다.

기본 창 장식은 운영체제 것을 사용합니다. 사용자 정의 타이틀바는 창 이동·최대화·창 메뉴·배율·보조 기술 동작을 동일하게 지원할 수 있을 때만 채택합니다.

6. 컴포넌트 계약

요소필수 동작과 상태
버튼동사 중심 레이블. 같은 작업 영역의 주 동작 하나에 강조색. hover·pressed·focus·disabled·pending 상태. 진행 중에는 중복 제출 방지.
입력항상 보이는 레이블. 힌트와 오류를 프로그램적으로 연결. 입력값 유지. 검증 실패 시 첫 오류로 포커스. placeholder는 레이블을 대체하지 않음.
목록·표선택·키보드 포커스·완료 상태 구별. 정렬과 필터 상태 표시. 다중 선택이 필요할 때만 체크박스 사용. 검색 결과 없음과 데이터 없음 구별.
대화상자의미 있는 제목. 진입 시 첫 적절한 요소에 포커스. Tab을 내부에서 순환. 닫으면 실행한 요소로 복귀. Escape로 닫되 미저장 데이터는 이탈 규칙 적용.
메뉴·명령 검색키보드와 마우스 모두 사용 가능. 방향키로 선택, Enter로 실행, Escape로 닫기. 검색 결과와 선택을 보조 기술에 전달.
피드백성공은 작업 위치 근처에 짧게, 중요한 오류는 지속 표시. 되돌리기처럼 행동이 붙은 알림은 자동으로 사라지지 않음.
아이콘Lucide 한 세트. 일반 18px, 버튼 내부 16px, 선 굵기 1.75. 동작 버튼은 접근 가능한 이름 제공. hover에만 필요한 정보를 숨기지 않음.

웹 구현에서는 키보드·포커스를 검증한 프리미티브나 네이티브 HTML을 우선 사용합니다. React라면 Radix·shadcn/ui를 이 토큰에 맞춰 사용할 수 있습니다. 이 패키지의 샘플은 프레임워크 의존성 없는 참고 구현이며, 모든 앱 컴포넌트를 대체하는 완제품 라이브러리는 아닙니다.

운영체제 단축키를 임의로 빼앗지 않습니다. 전역 호출 단축키는 앱 내부 단축키와 분리하고 사용자 설정으로 제공합니다. 일반 입력 중 단일 문자 단축키를 실행하지 않습니다. 한글 IME 조합 중에는 명령 실행과 검색 결과 확정을 중단합니다.

편집은 자동 저장 또는 명시적 저장 중 하나를 영역별로 일관되게 사용합니다. 자동 저장은 ‘저장 중 → 저장됨 → 실패’를 표시하고, 명시적 저장은 변경사항과 저장 가능 여부를 표시합니다. 미저장 내용이 있는 상태에서 다른 항목·화면·창으로 이동하면 저장 또는 변경사항 버리기를 선택하게 합니다.

되돌릴 수 있는 삭제는 보관 또는 휴지통으로 처리하고 되돌리기를 제공합니다. 영구 삭제·원본 덮어쓰기 등 복구 불가능한 동작은 구체적인 대상과 결과를 보여준 뒤 확인합니다. 파일 이동·일괄 이름 변경은 적용 전 미리보기와 적용 후 복구 수단을 제공합니다.

8. 로딩과 예외 상태

모든 주요 화면은 정상·비어 있음·검색 결과 없음·로딩·실패·권한 필요·오프라인 중 해당하는 상태를 설계합니다. 최초 빈 화면에는 무엇을 추가할지와 시작 동작을 표시합니다. 검색 결과 없음에는 검색어 수정이나 필터 해제를 제공합니다.

짧은 처리에 화면 전체 로더를 띄우지 않습니다. 작업이 이어지면 기존 내용을 유지하고 해당 영역에 진행을 표시합니다. 실제 진행률을 알 수 있을 때만 퍼센트를 표시합니다. 실패 시 입력과 선택을 보존하고 ‘다시 시도’ 또는 해결 경로를 제공합니다. 기술적인 상세 오류는 별도 상세 영역이나 로그에 둡니다.

오류 문구는 문제와 다음 행동을 설명합니다. 예: ‘폴더에 저장할 수 없습니다. 다른 위치를 선택하거나 쓰기 권한을 확인하세요.’ 완료와 실패를 토스트의 색만으로 전달하지 않습니다.

9. 테마와 움직임

첫 실행 테마는 시스템 설정, 밀도는 여유 모드입니다. 사용자가 명시적으로 고른 테마·밀도를 다음 실행에 복원합니다. 모든 화면·메뉴·팝업·오류 상태는 같은 테마를 사용합니다. 시스템 고대비와 글자 확대를 존중합니다.

피드백은 100ms, 일반 전환은 160ms, 대화상자 진입은 최대 200ms를 기준으로 합니다. 움직임은 위치 변화나 처리 상태를 설명할 때 사용합니다. 장식용 반복 애니메이션을 넣지 않습니다. 감소된 움직임 설정에서는 위치 애니메이션을 끄고 즉시 상태를 전달합니다.

10. 새 앱에 적용하는 순서

  1. 주요 작업 하나와 사용자 흐름을 정의하고 세 화면 패턴 중 하나를 선택합니다.
  2. tokens.json을 기준값으로 사용하고 styles/tokens.css와 공통 컴포넌트를 연결합니다. 네이티브 UI는 같은 역할을 플랫폼 리소스에 매핑합니다.
  3. 기본 데이터와 가장 긴 실제 텍스트를 넣어 화면을 구성합니다. 샘플 대시보드나 의미 없는 통계로 공간을 채우지 않습니다.
  4. 선택·편집·저장·취소·복구 경로와 필요한 예외 상태를 구현합니다.
  5. 라이트·다크, 두 밀도, 키보드만 사용, 작은 창, 200% 글자 확대, 오류·빈 상태를 확인합니다.
  6. 공통값을 바꿔야 한다면 토큰과 버전을 갱신하고 CSS를 다시 생성합니다. 개별 화면에 임의의 색상과 간격을 추가하지 않습니다.

IMPLEMENTATION-PROMPT.txt는 새 앱 작업에서 이 기준을 전달하는 지침입니다. README.txt는 실행과 파일 구성, verification.json은 이번 기준 구현에서 수행한 검증 결과를 담습니다. 이후 앱의 테스트 결과와는 구분합니다.

구현 완료 기준은 정상 화면 한 장의 모양이 아니라, 사용자가 키보드와 포인터로 핵심 작업을 끝내고 오류에서 복구할 수 있는지입니다. 네이티브 창 동작·파일 권한·저장 데이터·자동 업데이트·설치 패키지는 각 실제 앱에서 별도로 구현하고 확인합니다.

12. 한글 가독성과 출시 품질 기준

버전 1.1부터 글꼴·좁은 창·확대·입력 품질을 출시 조건으로 관리합니다. 화면의 구조가 맞더라도 읽기 어렵거나 내용과 동작이 잘리면 완료로 보지 않습니다. 아래 기준은 quality-gates.json과 함께 새 앱에 적용합니다.

한글 타이포그래피 기준

기본 서체는 Pretendard Variable 1.3.9, 비교 선택지는 SUIT Variable 2.0.5입니다. 일반 UI는 15px, 장문은 16px·행간 1.8, 보조 정보는 13px을 기본으로 하고 rem으로 매핑합니다. 밀집 모드에서도 글자를 줄이지 않습니다. 한글 자간은 0을 기본으로 하며 사용자의 글자 간격 조정을 허용합니다. 이 크기와 서체 선택은 프로젝트의 디자인 기준입니다.

한글·영문·숫자·문장부호가 섞인 실제 문장을 400·500·600 굵기로 비교합니다. 폰트 파일의 존재와 CSS 선언만 확인하지 않고, 한글에 실제 사용된 서체·획의 뭉침·받침과 구두점 잘림·줄바꿈을 확인합니다. 이모지처럼 의도한 대체 서체는 예외를 기록합니다. 어절 단위 줄바꿈을 우선하고 긴 경로와 공백 없는 문자열에는 비상 줄바꿈을 허용합니다.

기본 서체는 현대 한글 완성형 11,172자(U+AC00–U+D7A3)를 한 패밀리에서 모두 지원해야 합니다. SUIT 비교 모드에만 예외를 둡니다. 포함한 2,668자 외의 완성형 한글 8,504자와 em dash(U+2014)는 번들 Pretendard로 대체하며, 이 대체 범위의 실제 서체·획·행 높이·줄바꿈 검증은 대기 상태입니다. 문자 매핑(cmap)의 범위 검사는 실제 표시 검사와 구분합니다. NFD 자모의 직접 매핑이 없더라도 조합 처리 결과를 별도로 확인해야 하므로, 매핑 부재만으로 렌더링 불가를 단정하지 않습니다.

접근성 근거와 프로젝트 선택의 구분

  • WCAG Reflow를 참고해 세로로 읽는 콘텐츠는 320 CSSpx 등가 폭에서 정보·기능을 유지하도록 합니다. 표의 2차원 배치 예외는 해당 영역에만 적용합니다.
  • WCAG Resize Text는 200%까지의 글자 확대에서 정보·기능 유지를 요구합니다. 글자 크기 변경, 실제 브라우저 확대, Windows 배율은 서로 다른 검사로 기록합니다.
  • WCAG Text Spacing에 따라 사용자가 행간 1.5배, 문단 뒤 간격 2em, 자간 0.12em, 단어 간격 0.16em을 함께 적용해도 잘림과 기능 손실이 없어야 합니다. 해당 문자 체계에서 쓰이는 속성에 적용하며, 기본 디자인을 이 간격으로 정하라는 뜻은 아닙니다.

15·16·13px, 장문 행간 1.8, 높이 360px, 긴 문자열 길이, 실제 배율별 검사표는 이 프로젝트가 정한 품질 기준입니다. 이 문서와 일부 검사 통과가 전체 WCAG 준수 또는 접근성 인증을 의미하지는 않습니다.

출시 판정과 증거

  1. 정적 검사에는 파일·구문·토큰·자산 연결 결과를 기록합니다. 실행하지 않은 검사 코드는 ‘준비됨’, 화면을 확인하지 못한 항목은 ‘대기’로 남깁니다.
  2. 실행 검사에는 실제 실행한 화면·상태·환경·측정값·실패 내용을 기록합니다. 페이지 폭 검사만으로 내부 잘림이나 키보드 접근까지 통과했다고 판단하지 않습니다.
  3. 시각 검수에는 한글 획과 줄바꿈, 겹침, 하단 동작, 포커스가 보이는 화면 증거와 검수 일시를 남깁니다. Windows 배율과 실제 IME 입력은 실환경 기록을 추가합니다.
  4. 필수 게이트가 모두 통과하고 해결하지 않은 잘림·겹침·접근 불가 문제가 0건일 때만 releasePassed: true로 바꿉니다. 정적 검사만 통과했거나 필수 항목이 대기 중이면 출시 판정을 보류합니다.
